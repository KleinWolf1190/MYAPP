# MYAPP AI 協作規範

本專案預計使用 Gemini、ChatGPT 或其他 AI 工具協助開發。

## 1. AI 接手前必讀

AI 開始修改專案前，至少閱讀：

1. `README.md`
2. `doc/00-project-charter.md`
3. `doc/01-requirements.md`
4. 與本次任務相關的其他 `doc/` 文件

## 2. AI 的工作順序

```
理解需求
  ↓
檢查現有架構
  ↓
確認要修改的文件 / 模組
  ↓
提出或執行最小變更
  ↓
測試
  ↓
更新文件
  ↓
Git commit
```

## 3. 需求衝突處理

若使用者的新要求與既有文件衝突：

- 不要自行默默覆蓋。
- 先以最新明確需求為準。
- 同步修改相關設計文件。
- 在 commit message 或變更紀錄中說明。

## 4. 程式碼修改原則

- 不任意重寫與任務無關的程式。
- 不新增沒有需求依據的大型系統。
- 不把設定值硬編碼進程式。
- 新增第三方套件時記錄用途。
- 修改資料格式時考慮舊資料相容性。

## 5. 文件同步

凡是會影響以下內容的程式修改，都應同步更新文件：
- 使用者流程
- 資料結構
- API
- UI 導航
- 系統架構
- 安裝或建置方式

## 6. Git 慣例

建議 commit 使用簡單且可理解的前綴：

- `docs:` 文件
- `feat:` 新功能
- `fix:` 修正
- `refactor:` 重構
- `test:` 測試
- `chore:` 專案設定

## 7. 禁止事項

- 不提交機密資料。
- 不因「可能有用」而任意新增大量功能。
- 不在需求未確定時自行改變產品定位。
- 不刪除既有文件而不說明原因。
