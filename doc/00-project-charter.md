# MYAPP 專案章程

## 1. 目前定位

MYAPP 是一個預計以 **Unity** 開發的 APP。

目前尚未指定完整產品類型，因此這份文件先定義專案方法，而不先假設具體功能。

## 2. 核心目標

第一階段目標不是立即完成 APP，而是建立一套可以讓：
- 使用者
- Unity 開發者
- Gemini 等 AI 輔助工具

共同閱讀、修改與維護的專案規格。

## 3. 第一版必須回答的問題

### 產品
- APP 要解決什麼問題？
- 主要使用者是誰？
- 使用情境是什麼？
- APP 最重要的核心功能是什麼？
- 哪些功能屬於第一版，哪些延後？

### 平台
- Windows / Android / iOS / WebGL？
- 是否需要跨平台同步？
- 是否需要登入？
- 是否需要網路服務或雲端資料？

### 資料
- 資料由使用者建立，還是由外部資料來源提供？
- 是否需要本機資料庫？
- 是否需要匯入 / 匯出？
- 是否需要版本管理或雲端同步？

### 互動
- 主要操作是觸控、滑鼠鍵盤，還是兩者都支援？
- 是否需要拖曳、搜尋、篩選、排序？
- 是否需要動畫或 3D 操作？

## 4. 設計原則

### 文件優先
重要決策先記錄在 `doc/`，再進入實作。

### 最小可行產品
第一版優先驗證核心使用流程，不預先堆疊大量次要功能。

### 可維護
系統設計應讓功能可以獨立修改，降低 AI 或人工維護時的耦合。

### 可交接
任何 AI 接手工作時，都應能從 README 與文件理解目前專案狀態。
